## Layout

- `protocol/`: preregistration, frozen dataset, requests, run matrix, ablations, and fault scenarios.
- `annotations/`: three-state annotation guide and empty import templates.
- `results/`: append-only trajectory index plus derived CSV/JSON/figures after execution.
- `cost/`: append-only cost ledger. It must never exceed the preregistered category or total caps.
- `pilot/`: rejected preflight traces, official baseline grader output, checksums, and the disclosed protocol deviation.
- `preflight/`: machine-readable readiness state, pinned model metadata, and provider probe receipts; blocked snapshots are not passing receipts.
- `paper/`: ACM-style English paper source, bibliography, appendix, and build scripts.
- `reports/`: Chinese research report generated from the same frozen results.

## Commands

Run from `packages/autodrive-eval`:

```bash
bun test
bun typecheck
bun run validate
bun run plan
bun run boundary:plan
bun run pilot:plan
bun run analyze
```

Paid execution is fail-closed. It requires `run-eval --execute --executor <host-executor> --preflight <receipt> --artifact-root <root>` plus either explicit `--run-id` values or `--all`. The executor runs on the host, receives a per-run maximum cost, and must keep provider credentials outside the task container. Exit code 75 is the only retryable infrastructure failure, and it is retried once.

Before any paid call, validate the host-executor envelope with `verify-executor`. This mode strips provider credentials from the child environment, forces a zero-dollar pilot context, confines files to `dry-run/`, and never appends an experiment result. A paid `canary` requires a sealed canary preflight, exactly one primary-model run ID, and stores historical mechanism evidence under `canary/`. The separate `pilot` command executes only the frozen non-primary SWE-bench Verified task and writes a copied protocol, trajectory, ledger, and receipt under `pilot/`; neither command can append the formal result index.

The 2026-08-30 r4 through r7 pilot attempts all failed before provider admission. r4 exposed a missing `.gitignore` on a read-only `OPENCODE_CONFIG_DIR`; r5 exposed stale gzip metadata after Bun decoded a relayed response; r6 exposed a V2 Location startup race before the configured provider was committed; and r7 showed that the executor's V1 `options.apiKey` was not projected into the V2 runner credential field. All four attempts retained unchanged gateway spend and activity and produced no provider request artifact. Commits `55cc676f72`, `5efa37aa89`, `6f141c3e00`, and `8e4359a39a` cover the four defects.

The prospectively authorized r8 attempt crossed those gates and exercised the real worker/controller path: 18 worker and three controller requests produced three boundaries and durable decisions `continue`, `continue`, then timeout-safe `defer`; both automatic continuation inputs were admitted and promoted exactly once. The first-boundary grader passed all five P2P tests but failed the single F2P test. Final grading stopped before tests because the model patch and frozen test patch both modified `test_requests.py`, so neither forward nor reverse applicability check passed. The fail-closed run is an excluded charged evaluation failure, not an accepted pilot or ablation trajectory. Twenty responses have complete local usage totaling 123,052 prompt and 4,856 completion tokens; the final controller terminal response is missing from local artifacts. Eight stable account reads settled at USD 2.1923892, an observed account-window delta of USD 0.2470144 from the r8 baseline, not complete per-request attribution. No trajectory or ledger row was written, formal completion remains 0/384, and r8 cannot be rerun under its authorization.

Commit `13f6ea79f7` hardens that exception path without changing the conflict gate or experimental policy. After any post-start executor error, the host keeps the proxy alive while it performs the existing finite gateway-settlement wait, rereads request/response usage, samples settled account spend, writes a strict `failures/<run>/attempt-<n>.json` receipt that can never claim trajectory or ledger acceptance, and then rethrows the original error before cleanup. A pre-provider error skips settlement and spend polling. This is zero-cost implementation evidence only; it does not authorize or constitute another pilot.

The prospectively authorized r9 attempt started once from commit `8b628aaff5`, containing fix `13f6ea79f7`, and was accepted as a negative non-primary pilot. Six worker requests and one controller request all returned HTTP 200 with complete usage of 17,788 prompt and 2,226 completion tokens; accepted cost was USD 0.121062 and trajectory latency was 85.512 seconds. The task remained unresolved with F2P 0/1, P2P 5/5, Fix Rate zero, and no automatic or unsafe continuation. The controller eventually returned valid `continue` JSON 30.241 seconds after release, but v1.14 correctly persisted `defer` at the frozen 15-second deadline. Keeping the proxy alive through normal settlement captured the late response and complete spend evidence. The exception-receipt branch itself was not triggered by this successful executor return and remains zero-cost tested.

An offline startup check found that the task image already contained untracked `build/`. The accepted first and final patches are identical and contain only 65 paths below that directory, so their byte/file counts are environmental noise rather than model-change measurements. This does not change the official negative grade or pilot acceptance. The r9 row remains isolated from the 384 formal matrix and every ablation estimate.

The startup-baseline gate is now implemented without deleting image state. Before the worker prompt, the executor verifies the frozen HEAD and clean tracked files, records all untracked paths and roots, writes a Git tree plus content-addressed manifest/binary patch, and emits trajectory schema v4. Boundary and final patches are generated relative to that tree. Changes below startup-only roots are omitted from the model patch but retained as trace `excludedPaths`, so a charged run is still graded and counted. A zero-network run against the frozen r9 image reduced 65 startup paths and an 871,679-byte image patch to an empty model-relative patch. Historical schema-v3 evidence stays immutable; all boundary and formal rows must use schema v4.

The 48 formal task inputs are committed under `protocol/tasks/` and validated against the already pinned SWE-EVO Arrow digest. A pre-boundary zero-cost audit found that the runner had previously omitted their environment projection and that the upstream rows use four pytest parser variants, including one valid empty test patch. The runner now supplies the task-input root explicitly; the grader implements all four pinned upstream parser semantics and skips application only for that explicit empty patch. No boundary provider request or accepted source row existed when this correction was made.

Boundary data are built only from the separate 96-run source plan and never from formal result selection. `boundary:run` requires a fresh boundary-scope preflight and writes only below the external artifact root's `boundary/` directory under the USD 102 category. A stopped process with an attempt-one receipt is fail-closed: an operator must select exactly one run with `--resume-infrastructure`, and the CLI admits attempt two only from hash-valid, zero-request, zero-token, zero-spend evidence for a predefined setup failure. Attempts are artifact-isolated and attempt two is terminal. `annotations:extract` reconstructs controller inputs from canonical requests, Session transcripts, and boundary patches while removing reasoning and supervisor decisions. `annotations:prepare` creates a blinded JSONL packet plus an identity-bound CSV. `annotations:freeze` requires two distinct annotators, a distinct adjudicator, complete 180-ID coverage, Cohen's kappa at least 0.75, exactly 60 adjudicated examples per class, and a grouped 54/126 split.

A label-blind sample-size contingency is sealed before annotation. Only if the completed initial 96-run frame yields fewer than 180 extractable boundaries, all 48 tasks run once more under a disjoint repeat-2 augmentation namespace. RQ1 always uses the original frame alone; augmentation can feed only the balanced RQ3 classifier corpus and cannot stop early based on yield or labels.

The artifact also includes a disclosed independent-model annotation executor for sensitivity analysis; its receipts identify the method and model version, and its output is never called human annotation. The frozen five-row boundary ablation imports the production regex decision function for its zero-cost row and executes four controller-context rows under a separate 504-call preflight and budget. Summary and memory are parallel additions to the goal baseline: the trajectory-summary row is an offline information ablation, while the memory row matches the deployed supervisor's information sources.

## Integrity and privacy

- Dataset provenance is recorded in `protocol/swe-evo-48.json`.
- Each trajectory must record every ordered worker/controller request, resolved model version, canonical request artifact and SHA-256, model-metadata/preflight hashes, container digest, OpenCode commit, and raw trace SHA-256.
- Model keys must not be copied into task containers, JSONL/CSV, PDFs, LaTeX sources, logs, or archives.
- arXiv upload is outside this artifact and requires separate approval for authors, affiliations, email addresses, ordering, license, and the final PDF.
